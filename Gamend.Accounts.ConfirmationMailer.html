    Gamend.Accounts.ConfirmationMailer (gamend_core v1.0.1269)

    Copy Markdown View Source

    Sends a new account's confirmation email, off the request.

    Registration enqueues this in the transaction that inserts the user, so a committed account always has its email queued and the transaction holds the database for two inserts rather than an SMTP conversation. On SQLite the repo has a single connection, and a registration that sent its mail inline stalled every other query in the server for the length of the SMTP session.

    The job mints the token itself: a token in the job's args would sit in the jobs table in the clear. A failed send is retried with backoff, minting a new token each attempt (the unused ones expire). A job that outlives timeout/1 is killed, so a hung relay costs one mailers slot, never the database.
