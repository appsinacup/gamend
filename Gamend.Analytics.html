    Gamend.Analytics (gamend_core v1.1.1363)

    Copy Markdown View Source

    The one place aggregate numbers come from. Four families:

    • Activity & retention — DAU / WAU / MAU, new users per day, strict D1 / D7 / D30 cohort retention, payer conversion. Derived from user_activity_days (one row per user per UTC day seen, written by record_activity/2 from the last_seen_at touches in Gamend.Accounts), users.inserted_at for cohorts and purchases for payers.
    • Snapshot — snapshot/0: every context's live counters (players, lobbies, parties, quests, signaling, matchmaking, tournaments) composed once and cached, so the public stats page, the admin index and the /api/v1/stats endpoint show the same numbers instead of each calling six modules.
    • Economy flow — economy_flow/2: coins granted and spent per day per ledger reason, straight from ledger_entries.
    • Daily counters — count/3 + counts/2: named per-day counters for events that have no table of their own (a level finished, a start blocked by empty hearts). The game picks the keys; the engine sums them. families/3 reads them back grouped: a base key with its dimensions.
    • Events — track/3: one call that counts (the name, and the name per dimension) AND, for an account, keeps the row — who, when, every field — in analytics_events. A visitor's event is counted only. The counters answer "how many" forever; the rows answer what a sum cannot: how many distinct people did a thing (feature_summary/1: DAU / WAU / MAU, first-timers and D1 / D7 / D30 per feature), in what order, with what else. Writes are gathered by Gamend.Analytics.Buffer and landed in batches.

    Days are UTC, like every other period boundary on the server. "D7" means seen on the 7th day after the registration day, not "seen at any point in the first week" — the classic strict definition, so numbers compare with the ones stores and ad networks report.

    Reads are cheap enough for a dashboard on a small database; the composed views (snapshot/0, dashboard_stats/0) cache for a minute or a few. Nothing here is exposed to players except through the operator-gated public stats page.

    daily_series(days \\ 30, today \\ Date.utc_today(), opts \\ [])

    One row per UTC day for the last days days ending on today, oldest first: %{day, active, new_active, returning, wau, mau, stickiness, new_users, d1, d7, d30}. new_active are the accounts made that day and seen on it, returning the rest of active. wau / mau are the distinct users of the 7 / 30 days ending on that day, and stickiness is active ÷ mau of that day. A retention rate is nil when the cohort is empty, the horizon day has not happened yet, or the cohort is older than retention_since (Gamend.Analytics.Catalog.overview/0). Options: segment: (segments/0).

A cell is rate: nil until every account of the week has lived through it. Options: segment: (segments/0).

    track(name, dims \\ %{}, opts \\ [])

    @spec track(String.t(), map(), keyword()) :: :ok

    Records that something happened: name is counted for the day (count/3), once more per DIMENSION (name.lang:ro), and, when it has a user, the whole event — dims, user_id, the moment — is kept as a row in analytics_events. One call, so a counter and its event can never disagree.

    An event with no user (a visitor, a webhook) is counted and never kept: a row is there to say WHO, and a visitor has no id to say it with. On a site crawlers read, they were nearly every row.

    name is dotted [a-z0-9_], up to 64 chars ("web.game.finished"). dims is a map of the event's fields, atom or string keys of [a-z0-9_]:

    • a string, atom or boolean value is a dimension: a closed set the caller owns (a language code, a game, practice | daily), counted as its own key, so keep free text out of it;
    • an integer or float is a measure (a score, seconds): kept in the row, never counted;
    • nil is dropped.

    Options: user_id: (nil for a visitor: counted only; nulled on the kept row when the account is deleted), at: (default now). Buffered like count/3. Never raises: a bad name or field is dropped with a warning, the rest is kept.

    Analytics.track("web.game.finished",
  %{game: "hangman", lang: "ro", mode: :daily, score: 7, total: 10},
  user_id: user_id)
