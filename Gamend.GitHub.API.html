    Gamend.GitHub.API (gamend_core v1.1.1366)

    Copy Markdown View Source

    The GitHub REST calls a GitHub App makes, and the credentials that make them.

    A GitHub App speaks with three different tokens and it is worth keeping them apart by name:

    • the App JWT, signed here with the App's private key, ten minutes long, and good only for asking about installations and minting the next kind;
    • an installation token, one hour, scoped to the repositories one installation was granted, and what clones a private repository and writes a check run;
    • a user token, from the OAuth code a person brings back from GitHub, used exactly once to ask which installations they may see.

    Nothing here decides who may do what; that is Gamend.GitHub. This module only knows how to ask. Every call merges :github_req_options from :gamend_core's environment, which is how a test points it at a Req.Test stub.

    @spec app_jwt(String.t(), String.t() | nil) ::
  {:ok, token()} | {:error, :invalid_private_key}

    A JWT the App signs for itself. iat sits a minute in the past because GitHub rejects a token whose clock is ahead of its own, and exp stays under the ten-minute ceiling.

    {:error, :invalid_private_key} when the configured key is not an RSA private key in PEM. That is the operator's to fix, and every caller is on a path that has to end (a checkout, a check run), so it is an answer rather than a raise that left the job that asked running.
