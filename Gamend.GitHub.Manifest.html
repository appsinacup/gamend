    Gamend.GitHub.Manifest (gamend_core v1.1.1364)

    Copy Markdown View Source

    The server's GitHub App, described once, so GitHub creates it rather than a person filling in a form.

    GitHub has no API for creating or editing an App's settings: the callback URLs, the setup URL, the permissions all live on a page only a browser reaches. What it does have is the manifest flow: a form posts this JSON to github.com/settings/apps/new, the person signed in there presses one button, and GitHub redirects to redirect_url with a code that convert/1 trades for everything .env needs (id, slug, client pair, webhook secret and the private key) in one answer. mix gamend.github.app is that flow end to end.

    What the App is called, says and may do is the host's:

    config :gamend_core, Gamend.GitHub.Manifest,
  name: "Gamend Cloud",
  description: "Builds a Gamend server from your repository.",
  webhook_path: "/cloud/hooks/github",
  permissions: %{"checks" => "write"}

    permissions are added to the floor every App gets (contents and metadata read, to clone and list; email addresses read, so "Log in with GitHub" finds an account by its verified email). Without a webhook_path the App has no webhook and subscribes to nothing.

    Two things the manifest cannot say. The installation events (installation, installation_repositories) are not subscribable: every App with a webhook receives them, so only push is listed. And "expire user authorization tokens" has no field; GitHub turns it on for every new App, which is what the connect flow wants.
