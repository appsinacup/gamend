    Gamend.GitHub (gamend_core v1.1.1362)

    Copy Markdown View Source

    The server's GitHub App: who may use which installation, the credentials a job borrows from it, and what its webhook means.

    For a host that works on its customers' repositories: Forge builds them, Gamend Cloud builds a server from one. Core keeps what every such host needs (the App's settings, its tokens, the installations a user connected, the connect flow at /github/*, /admin/github, mix gamend.github.app); the host keeps what it binds to a repository (a project, a server) and the webhook route that acts on it.

    Two credentials, two owners

    The App's OAuth client id and secret are its identity to a person: Gamend.OAuth.Providers declares them as github, so "Log in with GitHub" is the same App, and the connect flow here reads the same pair. The App id, slug and private key are what mint installation tokens, and are declared on this module (GAMEND_GITHUB_*). Both are operator configuration; neither is a customer's, so neither lives in Gamend.Secrets.

    Who may use an installation

    GitHub decides. After the App is installed, GET /user/installations with the person's own token lists the installations that person may see, and those rows, only those, become theirs in github_installations. Trusting the installation_id GitHub appends to the setup redirect would let anyone type a number into a URL and claim somebody else's organisation. A host that binds something to an installation checks get_installation/2 first.

    Where the token goes

    Into git's environment (git_env/1), and nowhere else. A clone URL carrying it is written to the clone's .git/config, which a build may read; a log that prints the repository URL never had it.

    The webhook

    The App has one webhook URL, the host's route. The host verifies a delivery with verify_webhook/2 over the raw body, hands every verified one to installation_event/2 (which keeps this module's rows in step and says what the host has to unbind), and reads a push with push_event/1.

    git_env(installation_id)

    @spec git_env(integer() | nil) :: {:ok, [{String.t(), String.t()}]} | {:error, term()}

    The environment a git needs to clone through an installation.

    Empty for none. Otherwise the token rides in as an http.extraheader for github.com only: git reads it, nothing the clone writes holds it, and ps shows only the variable names. Prompting is switched off so a token GitHub refuses fails the clone rather than hanging the job.

    installation_event(arg1, payload)

    @spec installation_event(String.t() | nil, map()) ::
  {:deleted, integer()} | {:repositories_removed, integer(), [integer()]} | :ok

    The App's own lifecycle, from a verified delivery's X-GitHub-Event and payload. This module's rows follow it here; the answer is what the host has to unbind:

    • {:deleted, installation_id}: the App was uninstalled;
    • {:repositories_removed, installation_id, repo_ids}: the installation no longer reaches those repositories;
    • :ok: nothing for the host (a suspension, any other event).

    An uninstall is the customer withdrawing access, so what borrowed it stops the moment GitHub says so rather than at the next failed clone.

    @spec installation_token(integer()) :: {:ok, String.t()} | {:error, term()}

    Cached under Gamend.Cache rather than in the process: jobs for one installation run in parallel and each would otherwise mint its own, and GitHub counts those against the App.

    link_installations(map, code, redirect_uri)

    @spec link_installations(Gamend.Accounts.User.t(), String.t(), String.t()) ::
  {:ok, [Gamend.GitHub.Installation.t()]} | {:error, term()}

    Turn the code a person brought back into their installations.

    The user token is used for exactly one request and dropped: nothing here needs to act as the person later, and a token that is not stored cannot leak. What is kept is GitHub's answer, the installations, written as this user's. Ones GitHub no longer lists are removed, so revoking access on GitHub's side is enough to revoke it here.

    list_all_installations(opts \\ [])

    @spec list_all_installations(keyword()) :: [map()]

    Every installation on this server, newest first, for /admin/github.

    Each row carries the user who connected it and, when the host counts them (config :gamend_core, :github_usage, {module, function}, answering %{installation_id => count}), how many of the host's things use it in uses (nil when the host counts nothing). A suspended or unused installation is then visible as such: the first is GitHub's doing and the second is a customer who left.

    verify_webhook(raw_body, arg2)

    @spec verify_webhook(binary(), String.t() | nil) :: :ok | {:error, atom()}

    Verify a delivery's X-Hub-Signature-256 against the raw request body.

    Over the raw body, in constant time, and never over the parsed params, which are a re-encoding and would let a crafted payload pass a check its own bytes would fail. Refuses when no secret is configured: an endpoint anyone can POST to and that starts work must not be open by default.
