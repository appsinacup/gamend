    Gamend.Leaderboards (gamend_core v1.1.1371)

    Copy Markdown View Source

    The Leaderboards context.

    Provides server-authoritative leaderboard management. Scores can only be submitted via server-side code — there is no public API for score submission.

    Usage

    # Create a leaderboard
{:ok, lb} = Leaderboards.create_leaderboard(%{
  slug: "weekly_kills",
  title: "Weekly Kills",
  sort_order: :desc,
  operator: :incr
})

# Submit score (server-only): resolve the active leaderboard first and submit by ID
leaderboard = Leaderboards.get_active_leaderboard_by_slug("weekly_kills")
{:ok, record} = Leaderboards.submit_score(leaderboard.id, user_id, 10)

# List records with rank (use leaderboard id)
records = Leaderboards.list_records(leaderboard.id, page: 1, limit: 25)

    Keys

    A board can hold several rankings: a record is unique per user (or label) and key, and every read ranks within one key. "" is the default, a board with one ranking. A host keeping, say, a best per game and language on one board submits with key: "match|60|es_es" and metadata naming the parts; list_records/2 with key: :all and meta: reads across keys (best_per_user: true keeps each player's best of them). list_keys/2 names the keys a board holds, and list_records_above/3 the records just ahead of a score on one key. A board can show its keys as tabs and filters on /leaderboards (GamendWeb.LeaderboardViews).

    All time

    A :best board with seasons (all_time?/1: a start or an end date) has an all-time ranking too: every season of its slug read as one, each player's (or label's) best row of them, ranked. all_time: true on list_records/2, count_records/2, get_user_record/3 and list_keys/2 reads it, per key, from any season of the slug.

    Those rows are kept on a hidden board of their own, <slug>__all_time: a submit to a season raises it the way a :best submit does, an edited or deleted season row reads its owner's best again, and a deleted season refills it. So All time reads like any board, indexed and cached, however many seasons and players there are. Computing it from the seasons on every read took a second a page at 100,000 rows. The board is made and filled the first time it is asked for; rebuild_all_time/1 refills it for rows written around submit_score/5.

    Hidden boards

    hidden: true keeps a board out of list_leaderboards/1, list_leaderboard_groups/1 and their counts unless include_hidden: true is passed. Everything else reads it like any board.

    Guests

    When the host requires an account to be listed (Gamend.AccountRequired, :leaderboards), a guest's records stay on a public board but out of every read of it: lists, counts and ranks, so a guest moves nobody. The guest's own get_user_record/3 still answers, ranked where it would stand, with hidden: true. A hidden board keeps its guests (it is no one's public board), and guests: true reads them anyway (the admin's view).

    Whether a record is a guest's is stored on it (Record's guest), kept by the database: set from the user on insert, moved when the user registers (or loses their last identity). A listed read filters the record alone, on its own rank index (NOT guest); joining every record to its user took a second a rank at a million rows.

{:ok, record} = Leaderboards.get_user_record(leaderboard.id, user_id)

    invalidate_cache()

    @spec invalidate_cache() :: :ok

    Forget the cached leaderboard lookups.

    Every write in here does this already. It is public because a CALLER can also learn the cache is stale: get_active_leaderboard_by_slug/1 is cached for a minute, so a board deleted (or rolled back, under a test sandbox) hands out an id whose row is gone, and the next submit_score/4 fails on the foreign key. A caller that sees that can drop the lookup and try again rather than wait out the TTL.

    list_records(leaderboard_id, opts \\ [])

    @spec list_records(String.t(), keyword()) :: [Gamend.Leaderboards.Record.t()]

    Lists records for a leaderboard, ordered by rank.

    Options

    See Gamend.Types.pagination_opts/0 for available options, plus:

    • :key — the ranking to read (default ""), or :all for every key's rows ranked together.
    • :meta — a map, keeping only records whose metadata[field] equals each value (%{"game" => "match", "lang" => "es_es"}). Ranks are computed within the filtered set, because "the Spanish board" means first among Spanish, not 57th overall. That is the opposite of :search, which ranks over the whole key so a found player's real position is what shows.
    • :best_per_user — with key: :all, each player's (or label's) best row only: one board read across keys, a player once.
    • :guests — true lists guests' records on a public board too, when the host keeps them off it (Gamend.AccountRequired): the admin's view.
    • :all_time — true reads every season of the board's slug as one ranking (All time above), with :key and :search only. A board without seasons reads as itself.

    list_records_above(leaderboard_id, score, opts \\ [])

    @spec list_records_above(String.t(), integer(), keyword()) :: [
  Gamend.Leaderboards.Record.t()
]

    The listed records just ahead of score on one key, nearest first: the runs a player at that score would overtake next. Ahead means a strictly better score (higher on a :desc board, lower on an :asc one), so a tie is not ahead. Each record carries its rank.

    It needs no record of the caller's: a first-timer reads it with their first score, and a guest with theirs, though a guest's own record is not listed (Gamend.AccountRequired). list_records_around_user/3 needs the caller on the board. Labels' records are listed, like any.

    Options

    • :key — the ranking (default "")
    • :limit — how many (default 3)

    list_records_beside(leaderboard_id, record, opts \\ [])

    @spec list_records_beside(String.t(), Gamend.Leaderboards.Record.t(), keyword()) ::
  {[Gamend.Leaderboards.Record.t()], [Gamend.Leaderboards.Record.t()]}

    The listed records either side of record on its key: {above, below}, each nearest first, each carrying its rank. Above is sorting ahead of it the way ranks count (a better score, or the same one set earlier), below sorting behind it, so the ranks run on from the record's own: rank - 1, rank - 2… above, rank + 1… below. record must carry its rank (get_user_record/3's).

    A record kept off the board (a guest's, Gamend.AccountRequired) reads the same: its rank is where it would stand, and the rows behind it are numbered as if it stood there. Read off the rank index, as list_records_above/3 is: the key is never ranked whole.

    Options

    • :above, :below — how many on each side (default 1)

    merge_user_records(from_user_id, to_user_id)

    @spec merge_user_records(Ecto.UUID.t(), Ecto.UUID.t()) :: non_neg_integer()

    Moves from_user_id's records onto to_user_id, the way a guest's play joins the account they log in to (Gamend.Accounts.GuestMerge). The account's records are never lowered or deleted, and no hook or quest event fires: these scores were submitted once already.

    • best boards keep the better of the two (the board's sort order).
    • incr boards add the two up.
    • set and decr boards take the guest's record only where the account has none on that board and key.

    A guest's records left behind go with the guest account. Answers how many records reached the account.

    submit_score(leaderboard_id, user_id, score, metadata \\ %{}, opts \\ [])

    @spec submit_score(String.t(), Ecto.UUID.t(), integer(), map(), keyword()) ::
  {:ok, Gamend.Leaderboards.Record.t()} | {:error, term()}

    Submits a score for a user on a leaderboard.

    This is a server-only function — there is no public API for score submission. The score is processed according to the leaderboard's operator:

    • :set — Always replace with new score
    • :best — Only update if new score is better (respects sort_order)
    • :incr — Add to existing score
    • :decr — Subtract from existing score

    To submit to a leaderboard by slug, first get the active leaderboard ID:

    leaderboard = Leaderboards.get_active_leaderboard_by_slug("weekly_kills")
Leaderboards.submit_score(leaderboard.id, user_id, 10)

    Examples

    iex> submit_score(123, user_id, 10)
{:ok, %Record{score: 10}}

iex> submit_score(123, user_id, 5, %{weapon: "sword"})
{:ok, %Record{score: 15, metadata: %{weapon: "sword"}}}

    key: (default "") is the ranking within the board the score goes to; the operator applies per key.

    iex> submit_score(123, user_id, 23, %{"game" => "match"}, key: "match|60")
{:ok, %Record{key: "match|60", score: 23}}
