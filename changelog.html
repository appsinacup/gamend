    • [added] Group slugs, fixed member caps, and titles that may repeat. A group has a slug, its name in a URL, made from its title unless one is given (crimson-order, then crimson-order-2), unique among its creator's groups and changed by its admins; the groups page names a group as ?group=<owner>/<slug> (Gamend.Groups.full_slug/1, get_group_by_full_slug/1; an id still opens one), and the API's group has slug and takes it on create and update, as does the realtime Group message (field 15). GAMEND_GROUPS_MAX_MEMBERS fixes every new group's cap, and its forms stop asking it; GAMEND_GROUPS_UNIQUE_TITLES=false lets two groups share a title. Gamend.Slug makes and checks a slug for any host (Forge's projects use it). Migration 20261028120000 adds the column and fills it, and moves the title's uniqueness from the database to the changeset. Hosts: run the migration; translate Slug; regenerate the JS and Godot protobuf bindings (mix host.proto.gen) for a client to read the slug.

    • [changed] A table row opens what it lists. clickable_row/0, row_link/1 and row_control/0 (core components) make a click anywhere on a row follow its link, other buttons in it still working; the groups page's rows open their group, and a group is left from its own page, no longer from the list. The admin lists with an editor or a detail page open it from the row (users, groups, lobbies, parties, leaderboards and their records, quests, tournaments, KV, products, chat filter words, client sessions, results, analytics breakdowns), their Edit and View buttons gone (and the users list's link to a provider's profile URL), as do notifications and a tournament's players; a table with nothing to open is as it was.

    • [fixed] A member asking for their hidden group by id got 404. GET /api/v1/groups/:id checked membership with the group and user swapped, so only a stranger's check could pass; a hidden group now answers its members.

An item without one shows as before.

Nothing when unset.

    • [added] Invite links over the API, and a group's pending invites. GET, POST and DELETE /api/v1/groups/:id/invite_link read, make and turn off a group's link (admins; the answer has its token and website url), GET /api/v1/groups/invite_links/:token shows the group a token opens and whether the caller is in it, and POST /api/v1/groups/invite_links/:token/join joins through it. GET /api/v1/groups/:id/invites lists a group's pending invitations, whoever sent them (Groups.list_group_invites/3, count_group_invites/1), and any admin of the group may now cancel one (Groups.cancel_invite/2, DELETE /api/v1/groups/sent_invitations/:invite_id), not only its sender. The SDKs are regenerated.

    • [changed] The groups page after an invite. Under Invite, admins see the group's pending invites, with who sent each and Cancel. Someone invited stays in the search results and friends, marked Invited, rather than vanishing with "No results.". Until the reader picks a tab, the page opens on Invitations while some are pending, and on their groups once none are. An invite link's box says how many joined through it, without plural forms. Hosts: the group and invite-link strings are translated in every core locale.

    • [added] Group invite links. An admin shares a link from the group's page (Invite → Invite link: Copy, New link, Turn off), and anyone signed in who opens it joins as a member, hidden groups included (Gamend.Groups.InviteLinks; create_invite_link/2, delete_invite_link/2, get_invite_link/1, join_by_invite_link/2 on Gamend.Groups). One per group: a new one stops the old, and it stops when it expires (GAMEND_GROUPS_LINK_DAYS, 7; 0 turns links off) or its maker is no longer an admin. Joining takes the usual room checks and before_group_join hook (source "invite_link") and tells the link's maker. The page it opens, GamendWeb.UserLive.GroupJoin, is routed by gamend_authenticated_live_routes/2 at <groups>/join/:token (/users/groups/join/:token without groups:), signed in only. Migration 20261027120000 adds group_invite_links; the CopyText hook copies a field's value. No HTTP endpoint yet. Hosts: translate the new strings (Invite link, Create link, New link, Turn off, Copy, Copied, the join page's).

    • [fixed] The Invitations and Sent invitations tabs crashed for anyone with an invite. Gamend.Parse.uuid/1 takes the 36-character form only, and every place that picks between an id and something else asks it (the tournaments page had its own copy).

    • [fixed] Gamend.Containers failures say what podman said. A usage error ends with See 'podman create --help', and that hint was the whole reason ({:podman_failed, :create, 125, "See 'podman create --help'"}); the line before it is kept now (Error: unknown flag: --runtime).

    • [added] One-screen pages. <Layouts.app screen> draws no footer and no landing for one under the content, and the page neither bounces at its ends nor pulls to refresh (overscroll-behavior-y: none on the root): a game or a test scrolls only as far as its own content, and a tap that drags a little moves nothing.

    • [added] Gamend.Containers.copy_tar/3: a folder of a container, running or stopped, as a tar archive written straight to a file as podman produces it, never held in memory ({:error, :not_found} for a path that is not there). Gamend Cloud hands a server's stored files over with it.

    • [added] Gamend.Containers runs a container as a user, on volumes that user owns (user: in a spec and in output/3, owner: in create_volume/3, a :chown mount): someone else's code runs as a uid of its own rather than as root, which rootless podman runs as the host's podman user. An image that drops from root to its own user, as Postgres does, starts as that user, so the hardening floor's dropped capabilities hold.

    • [added] Changing a Stripe subscription's plan. Gamend.Payments.change_stripe_subscription/4 moves a running subscription to another product of the same period (a hosted server's size, a tier of a monthly plan): Stripe swaps its price, prorated and invoiced at once (always_invoice, error_if_incomplete, so a declined card changes nothing), and the purchase and its entitlement row move to the new product and key, keeping their period; end_trial: true ends a trial and charges in full from today. customer.subscription.updated follows a price changed in Stripe's Dashboard or portal the same way (Gamend.Payments.StripePlanChange). A Stripe adapter gains change_subscription_price/4.

    • [added] A GitHub App for hosts that work on their customers' repositories. Gamend.GitHub holds the App's settings (GAMEND_GITHUB_APP_ID, _APP_SLUG, _PRIVATE_KEY, _WEBHOOK_SECRET; its client pair is the GAMEND_OAUTH_GITHUB_* login's), installation tokens cached until they near expiry, git_env/1 that hands one to git through its environment, the installations each user may use (github_installations, written from GitHub's own answer, never from an id in a URL), their repositories, and the webhook's signature check, pushes and lifecycle (verify_webhook/2, push_event/1, installation_event/2). gamend_github_routes/0 is the connect flow at /github/connect, /github/callback and /github/setup (config :gamend_web, :github_return_to for where it lands), /admin/github lists every installation (with the host's count from config :gamend_core, :github_usage), and mix gamend.github.app --host <url> creates the App from a manifest the host names (config :gamend_core, Gamend.GitHub.Manifest) and prints its settings.     • [added] Other names a server answers on. GAMEND_HTTP_OTHER_HOSTS lists names besides GAMEND_HTTP_HOST, such as a custom domain behind a proxy that routes by Host; WebSockets accept them as origins, beside GAMEND_HTTP_HOST or the GAMEND_HTTP_ALLOWED_ORIGINS list. Before, Phoenix's default accepted only GAMEND_HTTP_HOST, so a page served under another name (the admin pages, a web build) could not open its socket. CORS and links are unchanged.

    • [fixed] An empty GAMEND_HTTP_ALLOWED_ORIGINS lets the game socket take any origin, as its docs said: Phoenix's default had refused every origin but GAMEND_HTTP_HOST, so a web build served elsewhere (itch.io, a CDN) got 403 on /socket while the API answered it. The pages' socket (/live, the session cookie) keeps to the server's own names and the list. With a list set, both sockets take it and the server's own names.

    • [fixed] A regex: entry in GAMEND_HTTP_ALLOWED_ORIGINS no longer breaks WebSockets. Phoenix's check_origin takes origins as strings, so the compiled pattern raised on the first socket; a list holding one is checked by GamendWeb.Http.origin_allowed?/2.

    • [added] Containers. Gamend.Containers drives long-lived OCI containers and their images through the podman CLI (create, start, stop, pause, kill, update limits, logs, exec, volumes, pull, tag and untag, the machine's info/0 and every container's stats/0, a one-shot output/3 that takes limits and a runtime for a build of someone else's code), with a hardening floor on every container and secrets through a 0600 env file (write_env_file/2). update/2 takes CPUs, memory and pids together: podman 5 drops the limits an update leaves out. Networks (create_network/2, internal ones included, and networks:/network_alias: in a spec) put a server and its database on a network of their own. build/2 builds an image from a Dockerfile with a target, build args, labels, limits, a runtime and a time limit, gives its output as it comes, and answers the image's id and the end of the log; a Dockerfile outside the build context, or reached through a symlink, is refused. For hosts that run other programs beside themselves: Gamend Cloud runs a server per customer with it, and Forge its build and signing sandboxes.

    • [fixed] Players dropping at once no longer run a server out of memory. A thousand players dropping together ran a 1 GB server out of memory. It now reads the one key from the shard's table, and the other presence reads paid the same copy and now read the same way through Gamend.Presence.keys/1: a signaling room's peers on every relayed message, the room counts in the server stats, and a lobby's spectator count and list, once per lobby in a listing. The slow-query log (Gamend.Repo.SlowLog) did the same harm a second way: naming each frame's application copied every loaded application's module list into the caller, ~360 KB a line, and when the pool is what is slow every waiting query logs at once.
