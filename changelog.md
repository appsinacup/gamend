# November 2026

- [added] **Admin → Analytics → Time: how long accounts spend in the game.** Worked out from the rows already stored, nothing new collected (`Gamend.Analytics.TimeSpent`): an account's analytics events and its plays' moves (`results.started_at`, `result_events.elapsed_ms`), sorted, with every gap of at most 5 minutes counted as time spent. The average and median per account on a day it came, per account over the window, the total, per day, how the account-days spread, and where the time goes: each gap filed under the area of the moment it began (an event's group, a play's kind). A floor: the time after an account's last move of a visit is not counted, and a visitor with no account leaves no rows. **Hosts:** say how your rows read under `time` in the catalogue's `overview/0` (`idle_seconds`, `spans` for a start and an end with nothing stored between, `results`, `dim`, `areas`, `labels`; `Gamend.Analytics.Catalog.overview/0`).
- [added] **A game signs in with an emailed code, its magic link.** `POST /api/v1/login/code` (`email`) emails six digits, and `POST /api/v1/login/code/confirm` (`email`, `code`) answers a session, as the site's magic link signs in: a confirmed account keeps its password and sessions, one not yet confirmed is confirmed. Both answer as the password reset's do, with its code, lockout and lifetime. The Balaur SDK signs in with `client::login_with_code`, the Godot SDK with `authenticate_request_login_code` and `authenticate_login_with_code` ([Authentication](/docs/authentication)).

- [added] **A game sets a forgotten password with an emailed code.** `POST /api/v1/password/reset` (`email`) emails six digits, and `POST /api/v1/password/reset/confirm` (`email`, `code`, `password`) sets the new password and answers a session, as `register/confirm` does: a client with no page to open a link in no longer sends its player to the website. The first answers `{"ok": true}` whatever the address; the second shares the confirmation code, its lockout and its lifetime, confirms an account that was not, and never answers `409`. The Balaur SDK signs in with `client::reset_password`, the Godot SDK with `authenticate_request_password_reset` and `authenticate_reset_password` ([Authentication](/docs/authentication)).
- [fixed] **Sign in with Apple on a server without its client id answers `503 apple_not_configured`**, as Google's does, not a 500: the web and iOS code exchanges raised when `GAMEND_OAUTH_APPLE_CLIENT_ID` or `GAMEND_OAUTH_APPLE_IOS_CLIENT_ID` was unset.
- [added] **A board's rows carry what it names of their players' metadata.** A leaderboard's `user_metadata_keys` (top-level keys or dotted paths, `["player.pass_level"]`; `[]` by default) puts those values of each player's `users.metadata` on every record as `user_metadata` (`{"player": {"pass_level": 7}}`), read with the row, so a level shown beside the name is today's, not the best run's. Set on create or update (a plugin, the admin API, the admin page); the board lists them. Rows are public: name nothing private. It replaces a record's `mark` and `config :gamend_web, :user_mark` (`CoreComponents.user_mark/1`), added earlier this month and now removed: one host's number in core's API, which nothing in core drew. **Hosts:** drop `:user_mark` and name the value's path on the board. **Clients:** read `user_metadata` on a record, not `mark` ([Leaderboards](/docs/leaderboards)).
- [fixed] **The C++, Unreal, C#, Unity and Rust SDKs read every protobuf event again.** The server encodes WebRTC signalling, plays, bans, friendships, matchmaking tickets and peer signalling as protobuf messages since this month, and these SDKs' event tables had no row for them, so a protobuf client dropped them: the WebRTC answer never arrived and its connection failed. Each table now has the server's every event.
- [added] **Every file field takes a dropped file.** `<.file_drop upload={@uploads.avatar} input_class="file-input" />` (`GamendWeb.FileDropComponents`, imported by `use GamendWeb, :html`) draws a LiveView upload's input inside a zone that is its `phx-drop-target`; around a plain `<input type="file">` (its inner block, or any element marked `data-file-drop`) `file_drop.js` sets the input's files from the drop, as many as `multiple` and `accept` allow, and fires `input` and `change`, as a pick does. A file over the zone rings it in the primary colour (`gamend.css` `.file-drop`); the input stays the control a click and the keyboard reach. Core's avatar, group icon, report screenshot and admin storage fields use it. **Hosts:** wrap a `live_file_input` in it.
- [added] **`ffmpeg` in `gamend-builder`**, for audio a host makes at run time (Polyglot trims a text-to-speech take with it). The `full` image has it too; the `release` runtime image does not.
- [added] **A report kind can take a report elsewhere.** A kind's optional `take/1` answers `:taken` once it has put the report in a place of the host's own (a word's translators): no row, no admin alert, no image, and `Reports.create/2` answers `{:ok, :taken}`; the API's receipt is `{id: null, status: "taken"}` ([Reports](/docs/reports)).
- [changed] **A request with the wrong types is refused, not crashed on.** Every API request is checked against its OpenAPI operation before the action runs and answered `422 validation_failed` per field (`GamendWeb.Plugs.RequestContract`); a channel command against its row in `GamendWeb.RealtimeCommands`, which now types each key (`GamendWeb.ChannelContract`); a LiveView event against its `event("name", key: type)` declaration (`GamendWeb.LiveEvents`). Before, a list where a string belonged reached the action and answered 500, took a channel down or remounted a page. **Clients:** a value the document types wrongly is now a 422. **Hosts:** a host channel, LiveView or controller gets the checks through `use GamendWeb, :channel`, `:live_view` and `:controller`; declare your events (an event a `:handle_event` hook takes too, through `GamendWeb.LiveEvents.hook/2`), and an API route needs its operation to be checked ([API conventions](docs/specs/api-conventions.md#requests)).
- [fixed] **A hero's or a section's column no longer jumps as the page loads.** Its two columns were written media first and swapped by `order`, so a page painted while its HTML streamed in drew the media alone in the first column, then moved it across when the text arrived (a home page's language panel, 436px). The columns are written in the phone's order and placed in the grid (`row-start-*`, `md:col-start-*`); what is drawn is unchanged.
- [added] **A link that loads its page is fetched as it is pressed.** `live_nav.js` (`startPressPrefetch`) adds a speculation rule for the link's page on `pointerdown`, so the click a moment later finds it on its way or in: a page that is a full load (a controller page, a page from a controller page) opens 100-300 ms sooner. A link the page follows over its socket, a language switch, a link with a method and `[data-no-prefetch]` are not fetched; on a press, not a hover, so nothing is fetched that is not opened. The browser CSP allows `'inline-speculation-rules'` (JSON only, no script). Chrome and Edge; elsewhere nothing changes.
- [changed] **The sidebar's and tab bar's links are named classes** (`gamend.css`: `.side-link` and its states, and the `nav-tone-active` / `nav-tone-ring` utilities for a link's own page), not their utilities written out on every link of every page and join. They look the same.
- [fixed] **A timestamp keeps its width as the script says it again.** `<.timestamp>` and `<.duration>` hold their text with no newline or indentation around it, which drew as spaces until `local_time.js` wrote the reader's text, 4px narrower.
- [fixed] **The sidebar's icons are there with the page.** A `hero-*` icon is a mask of its file, which the browser asks for only once the stylesheet is in, so a first visit painted the sidebar and tab bar without their icons. The root layout preloads those links' icons beside the stylesheet (`HostLayoutNavigation.shell_icons/2`, the file a class masks by `GamendWeb.Icons.class_path/1`; a link the tab bar leaves out from `md` up only).
- [fixed] **A host's hooks run before the first paint.** The root layout loads each `extra_hook_modules` entry as a `<script type="module" blocking="render">` (it was only preloaded, then run by `app.js`'s `import()`, a frame or more after the first paint; as a plain module script a first visit, not cached yet, still painted before it), so what a host's module does at load, such as measuring a heading to fit its row, is done before the page is drawn. Keep the module small and without static imports: the first paint waits for it as for the stylesheet. `app.js`'s import gets the same instance.
- [fixed] **A closed language menu fetches no flags.** The site-language rows' flags are backgrounds (`flag/1`'s `deferred`), and a closed `<details>` dropdown's list was still laid out: every page fetched ~30 flags half a second after its socket joined. A closed menu's rows draw none (`gamend.css`); each row is one class (`locale-option`, `locale-option-current`, `locale-option-flag`), ~4 KB less in every join.
- [changed] **The loading bar waits a second for a page over the socket.** A live navigation, a patch and a join show `topbar` after 1 s (a form and a `phx-page-loading` click keep 300 ms): a page opened over the socket is a round trip and its mount, and the bar at 300 ms read as a reconnect.
- [changed] **A registration's code still works after its link was opened.** A player who registered in a game and confirmed by the email's link on a computer finishes in the game with the code, which sets the password and signs in; the link no longer spends it. Once the account has a password the right code answers `409 already_confirmed`, so the game logs in instead. The Balaur SDK's email sign-ins send a guest's session along, so the guest's progress joins the account ([Authentication](/docs/authentication)).
- [added] **A game client's guest keeps what it did when it signs in.** Logging in by email, confirming a registration's code and signing in with a provider over the API now merge the guest whose access token the request carries into the account, then delete the guest, as the website's sign-in does (`GamendWeb.UserAuth.merge_guest/2`); any other token there is ignored, never refused. The Balaur SDK renews a token about to expire before a call ([Authentication](/docs/authentication)).
- [added] **The account's preferences, live on every device.** A client reads what it may set on the account (the theme, and the host's `:client_preferences`) as the row `preferences`, its owner's only, and sets one with `PUT /api/v1/me/preferences`; each change, from the site's page or a client, pushes it again. The key `preferences` is core's computed row now: a host that stored a row under it renames that, or replaces core's row with its own. A host's allowed values can be a `{module, function}` (the languages it serves), and a computed row can now name the least its reader must be (`access: :owner_only`), which no `before_kv_get/2` answer opens ([Key-Value Store](/docs/key-value)).
- [added] **A family of computed rows, one a part.** A computed key ending in `*` (`"word_pools:*"`, worked out `from: ["words:*"]`) is a row for every part (`word_pools:fr`), its function handed the part (`part: "fr"`), and a write of `words:fr` moves `word_pools:fr` alone ([Key-Value Store](/docs/key-value)).
- [added] **`config :gamend_web, :breadcrumbs, false`** draws no breadcrumb trail in the navbar; the trail still sets each page's Back link.
- [changed] **Under 1280 px the sidebar is always its rail**, its Collapse button not drawn, so a page keeps its width; from 1280 px the reader's choice stands (`side_nav.js`).
- [added] **The navbar can leave room for a page's own row** (`--nav-reserve` on `#main-navbar`, px): the auto layout's stages beside the sidebar are measured against the room left after it, so the bar falls to its icons, its avatar or its menu before the page's row is cut (`navbar_fit.js`). Change it, then dispatch `gamend:side`.
- [added] **Revenue on Admin → Payments**: lifetime, this month, last month and the last 30 days, net of refunds and per currency, with a column per month and totals by provider and product. An App Store purchase keeps the price Apple's signed transaction names. **Hosts:** run the migration, which fills the table from the purchases already paid ([Payments](/docs/payments#revenue)).
- [added] **Any member can fill their lobby from the queue.** When `before_matchmaking_join/2` answers `Gamend.Matchmaking.Constants.member_backfill()` as `true`, a player who queues alone from a lobby they sit in fills it, host or not. A backfill ticket now fills its lobby while its holder sits there, not while they host it.

- [added] **Computed rows**: a key-value row the host works out from other state (`config :gamend_core, :computed_rows`), read and subscribed to like a stored one and stored nowhere; a client is pushed `kv_updated` when what it is worked out from moves ([Key-Value Store](/docs/key-value)).
- [added] **The API sends what the quests and leaderboards pages draw**: a quest's `action`, `note` and `lock` and a board's `action` for the reader, a board's `all_time`, records searched and all-time, and each row's `avatar_url`, `title`, `title_class` and `badge`.
