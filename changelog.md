# October 2026

- [added] **`Gamend.Containers` runs a container as a user, on volumes that user owns** (`user:` in a spec and in `output/3`, `owner:` in `create_volume/3`, a `:chown` mount): someone else's code runs as a uid of its own rather than as root, which rootless podman runs as the host's podman user. An image that drops from root to its own user, as Postgres does, starts as that user, so the hardening floor's dropped capabilities hold.
- [added] **Changing a Stripe subscription's plan.** `Gamend.Payments.change_stripe_subscription/4` moves a running subscription to another product of the same period (a hosted server's size, a tier of a monthly plan): Stripe swaps its price, prorated and invoiced at once (`always_invoice`, `error_if_incomplete`, so a declined card changes nothing), and the purchase and its entitlement row move to the new product and key, keeping their period; `end_trial: true` ends a trial and charges in full from today. `customer.subscription.updated` follows a price changed in Stripe's Dashboard or portal the same way (`Gamend.Payments.StripePlanChange`). A Stripe adapter gains `change_subscription_price/4`.
- [breaking] **Key settings take the key itself, never a path to its file.** `GAMEND_PUSH_FCM_CREDENTIALS`, `GAMEND_PUSH_APNS_PRIVATE_KEY` and `GAMEND_OBSERVABILITY_METRICS_TOKEN` no longer read a file they name, and `GAMEND_PAYMENTS_APPLE_PRIVATE_KEY_PATH` and `GAMEND_PAYMENTS_GOOGLE_PLAY_SERVICE_ACCOUNT_JSON_PATH` are gone. **Hosts:** put the file's contents in the setting (`GAMEND_PAYMENTS_APPLE_PRIVATE_KEY`, `GAMEND_PAYMENTS_GOOGLE_PLAY_SERVICE_ACCOUNT_JSON`, and the three above); a path left there is read as the key and fails as an invalid one.
- [added] **The signaling channel's rate limits on the admin pages**, beside the WebSocket and ICE ones.
- [added] **A GitHub App for hosts that work on their customers' repositories.** `Gamend.GitHub` holds the App's settings (`GAMEND_GITHUB_APP_ID`, `_APP_SLUG`, `_PRIVATE_KEY`, `_WEBHOOK_SECRET`; its client pair is the `GAMEND_OAUTH_GITHUB_*` login's), installation tokens cached until they near expiry, `git_env/1` that hands one to `git` through its environment, the installations each user may use (`github_installations`, written from GitHub's own answer, never from an id in a URL), their repositories, and the webhook's signature check, pushes and lifecycle (`verify_webhook/2`, `push_event/1`, `installation_event/2`). `gamend_github_routes/0` is the connect flow at `/github/connect`, `/github/callback` and `/github/setup` (`config :gamend_web, :github_return_to` for where it lands), `/admin/github` lists every installation (with the host's count from `config :gamend_core, :github_usage`), and `mix gamend.github.app --host <url>` creates the App from a manifest the host names (`config :gamend_core, Gamend.GitHub.Manifest`) and prints its settings. Forge and Gamend Cloud use it. **Hosts:** run the migrations; add the routes where you want them.
- [added] **Other names a server answers on.** `GAMEND_HTTP_OTHER_HOSTS` lists names besides `GAMEND_HTTP_HOST`, such as a custom domain behind a proxy that routes by `Host`; WebSockets accept them as origins, beside `GAMEND_HTTP_HOST` or the `GAMEND_HTTP_ALLOWED_ORIGINS` list. Before, Phoenix's default accepted only `GAMEND_HTTP_HOST`, so a page served under another name (the admin pages, a web build) could not open its socket. CORS and links are unchanged.
- [fixed] **An empty `GAMEND_HTTP_ALLOWED_ORIGINS` lets the game socket take any origin**, as its docs said: Phoenix's default had refused every origin but `GAMEND_HTTP_HOST`, so a web build served elsewhere (itch.io, a CDN) got 403 on `/socket` while the API answered it. The pages' socket (`/live`, the session cookie) keeps to the server's own names and the list. With a list set, both sockets take it and the server's own names.
- [fixed] **A `regex:` entry in `GAMEND_HTTP_ALLOWED_ORIGINS` no longer breaks WebSockets.** Phoenix's `check_origin` takes origins as strings, so the compiled pattern raised on the first socket; a list holding one is checked by `GamendWeb.Http.origin_allowed?/2`.

- [added] **Base images and one deploy script for hosts.** `ghcr.io/appsinacup/gamend-builder:elixir-1.20` (Elixir, the system packages, Rust, Hex and Rebar, and the `gamend-build-plugins`, `gamend-copy-static` and `gamend-start` commands), `gamend-runtime:trixie` (what a release links against, and `gamend-release-start`) and `gamend-backup:18` (a verified daily dump of a Postgres database), published on every change and weekly (`docker/README.md`); Gamend's own image is built on them. `deploy/gamend-deploy` deploys a compose app on its host (checks, build, start, wait until healthy, prune), set by the app's `deploy.conf` and started by a copy of `deploy/rebuild.sh` (`deploy/README.md`). **Hosts:** start your Dockerfile `FROM` the builder and drop the steps it covers; a backup service is `image: ghcr.io/appsinacup/gamend-backup:18`.
- [added] **Containers.** `Gamend.Containers` drives long-lived OCI containers and their images through the `podman` CLI (create, start, stop, pause, kill, update limits, logs, exec, volumes, pull, tag and untag, the machine's `info/0` and every container's `stats/0`, a one-shot `output/3` that takes limits and a runtime for a build of someone else's code), with a hardening floor on every container and secrets through a 0600 env file (`write_env_file/2`). `update/2` takes CPUs, memory and pids together: podman 5 drops the limits an update leaves out. Networks (`create_network/2`, internal ones included, and `networks:`/`network_alias:` in a spec) put a server and its database on a network of their own. `build/2` builds an image from a Dockerfile with a target, build args, labels, limits, a runtime and a time limit, gives its output as it comes, and answers the image's id and the end of the log; a Dockerfile outside the build context, or reached through a symlink, is refused. For hosts that run other programs beside themselves: Gamend Cloud runs a server per customer with it, and Forge its build and signing sandboxes.
- [added] **A server-wide player cap and a sign-in gate.** `GAMEND_LIMITS_MAX_SOCKETS` caps every user's sockets together on an instance, and `GAMEND_LIMITS_MAX_LOGINS_IN_FLIGHT` answers sign-ins past that many at once with 503 and `Retry-After` (`GamendWeb.Plugs.LoginGate`), so a reconnect storm queues at the clients and not in a small server's memory. Both off by default.
- [added] **Products sold once per subject.** A product whose `grant_config` has `"per_subject": true` grants `"<key>:<subject>"`, the subject being the checkout's `metadata["subject"]` (a server, a character), so one account may hold it for several; a checkout without a subject is `:subject_required`, and plan upgrades never apply to such a product (`Gamend.Payments.per_subject?/1`, `purchase_entitlement_key/1`).
- [added] **Results.** What a play leaves: one row per play per player and its events in order (`Gamend.Results`: `start/3`, `record/4`, `finish/1`), pushed to the player's socket as they are written, read over the socket (`results:list`, `results:get`, `results:events`) or `GET /api/v1/results`, with each event key's count and sum at a glance and `/admin/results` to browse them; a guest's results join the account they sign in to. **Hosts:** run the migrations.
- [added] **A sidebar, link tones and an account menu button.** `navigation.layout: "sidebar"` puts the plain primary links down the page's start edge from `md` up (`HostLayoutNavigation.side_nav/1`): open with their labels wherever it shows, a rail where the reader collapsed it (remembered per browser, `<html data-side="rail">`) or on a full-screen page; on a phone they are a tab bar along the bottom (`tab_nav/1`), less any marked `"mobile": "hidden"`. `"auto"` keeps them in the bar wherever it fits the window with their words, never as icons alone, and shows the sidebar where it does not (`side` in `<html data-nav>`). A link's `"tone"` colours its icon and the page's own tint from the host's `--nav-tone`; `navigation.menu_button: "account"` opens the menu from the reader's avatar. Presentation pages bleed to `--bleed-w`, the page's width less the sidebar. **Hosts:** declare `Collapse` and `Expand` for translation.
- [changed] **gamend.org and the `gamend starter` template show the navigation layouts.** Their links are flat, each with a `"tone"` coloured in `theme.css` (Play, Leaderboards, Quests, Tournaments, Groups, Blog, Guides), under `"layout": "auto"` and `"menu_button": "account"`; Changelog and Roadmap are in the footer, and the search palette still finds them. **Starter projects:** copy `theme/config.json`'s `navigation` and `static/theme.css` to get the same.
- [changed] **Log in and Register are two buttons** in the bar wherever it shows, in place of a visitor's Account dropdown; Register is the primary one, Log in on its own page. A guest account gets the same two and no avatar menu in the bar. Where the bar does not fit, a phone always, they stay in the menu. They, or the reader's menu, are the bar's last item, after the language; the bar, the sidebar and the tab bar sit on `base-200` with a `base-300` hairline.
- [changed] **The navbar fits itself.** It measures what it has room for, not the `xl` breakpoint: links spelled out, then as icons (the label as tooltip), then without the reader's name, then the menu. `<html data-nav>` names the stage; each stage's width is kept per language, so the next page draws the right one first. The language button is the flag and a chevron at every width, the language's name on hover and for a screen reader.
- [changed] **Page titles a host can fit to one line.** `page_title/1` carries `heading-title` and `fit-*` classes, and the title rows of core's pages are `data-heading-fit`, so a host that measures a heading row (the stage in the row's `data-heading`) drops the mark and shrinks the words where the row has no room. **Hosts:** without those styles the classes do nothing.
- [changed] **Quieter pages.** `config :gamend_web, :back_link, false` turns every Back button off, core's pages included, for a host whose navigation is always on screen; `config :gamend_web, :breadcrumb_depth, n` draws the navbar's trail only from `n` crumbs past home (the `BreadcrumbList` markup is unchanged). A panel has no shadow, and the background icon layer is fainter (4% light, 5% dark).
- [removed] **Lobby snapshots**, their tables, `/admin/lobby_snapshots` and the capture after every hook; results replace them. Rolling the migration back brings the tables back empty. **Hosts:** drop `GAMEND_LOBBY_SNAPSHOTS_*` and `GAMEND_RETENTION_LOBBY_SNAPSHOTS_*`.
- [added] **Client calls a host app answers.** `config :gamend_core, :host_rpc_modules, %{"name" => MyApp.Rpc}` makes a host module callable as a plugin is (`call_hook` with `plugin: "name"`), from code that is the host's own; a plugin of the same name wins.
- [added] **Guests keep their progress.** The website makes guest accounts, and a guest who registers or signs in keeps what they did (`Gamend.Accounts.GuestMerge`, the `merge_user_data/2` hook), then returns to the page they came from (`?return_to=`). **Hosts:** implement `merge_user_data/2` for keys both accounts can hold, and pass `?return_to=` instead of setting `:user_return_to`.
- [added] **Features a guest registers for.** `config :gamend_core, Gamend.AccountRequired, [:quest_claims, :leaderboards]` keeps quest claims and leaderboard places for registered accounts, on the website and the API alike.
- [breaking] **Registering takes no password**: the emailed code confirms the address. A crashing game hook answers 500 without details.
- [added] **Bans.** Ban an account for a while or for good, with a reason (`Gamend.Bans`, `/admin/bans`, the admin API); a banned account answers 403 `account_banned` and sees `/suspended`. `after_ban_created/1` and `after_ban_lifted/1` fire for every ban, and plugins can place bans.
- [breaking] **IP bans and chat mutes are bans too**, kept as history after they end. **Hosts:** run the migrations; `GamendWeb.IpBanSync` is `Gamend.Bans.Sync` and `Gamend.Chat.Mute` is `Gamend.Bans.Ban`; `Gamend.IpBans`, `/admin/chat/mutes`, `/api/v1/admin/chat/mutes` and `after_user_muted/1` are gone (use `/api/v1/admin/bans` with `kind: "chat"` and `after_ban_created/1`).
- [changed] **Quests**: periods on the player's clock (`:quest_clock, :player`), a card that leads to where the quest is done (`:quest_action`), finished quests that wait for their claim, and repeat quests that bank each run.
- [added] **Leaderboards with several rankings**, drawn as tabs and filters (`"views"` metadata, `:leaderboard_views`), an All time tab on a seasonal best-score board (`all_time: true` on the reads), the rows beside a record and at the bottom (`list_records_beside/3`, `list_records_last/2`), boards that can be hidden, a button to where a board is climbed (`:leaderboard_action`), and the same over the API (`key`, `/records/above`, `/keys`). **SDKs:** regenerated; Balaur's `get_my_record` takes `options`.
- [added] **Analytics events and tabs.** `Gamend.Analytics.track/3` keeps a row per event, `/admin/analytics` has Overview, Features, Explore, People, Counters and Economy tabs, a host describes its events (`:analytics_catalog`), and a reader back on their cookie counts as active. The Overview rates each number Low, Fair or Good with its meaning on hover, and shows new against returning accounts, return visits, weekly cohorts, activation, a funnel and money; stickiness is the last 7 full days' average, and D1 / D7 / D30 say how many accounts they pool. **Hosts:** run the migration; set the first fully counted day, the activation events, the funnel, the trial keys and the bands in the catalogue's `overview/0`.
- [added] **Stripe payments, end to end**: refunds within 14 days, resuming and upgrading, free periods, an hourly sweep for lost webhooks and `mix gamend.stripe.setup`. **Hosts:** set the webhook to API version `2025-11-17.clover`.
- [added] **Reports.** Players report from `/report` or the API, admins work the queue at `/admin/reports`, and a host adds its own kinds and a reward.
- [added] **One player card** (`player_card/1`: the avatar, the name cut with an ellipsis, a line under it) on the leaderboards, the account menu and tournament entries; a host names the line with `config :gamend_web, :user_title, {mod, fun}` (or the old metadata path).
- [added] **Pages**: a Back button and a title icon on every page, navbar links and counts that follow the reader, presentation pages drawn for a signed-in reader, and an `/admin` card for every admin page (`:admin_cards`). **Hosts:** a page that deletes itself navigates away with `replace: true`.
- [added] **A site in fewer languages.** `config :gamend_web, :locales, ["en"]` narrows the languages core's catalogue holds to the ones a host serves; with one, no language switcher is drawn, and a reader who chose another language gets `en`.
- [added] **Website feature switches** for the store, chat, groups, friends, tournaments, the game (`play`), the payments API and the language switcher's flags; a page, link or guide marked with a switched-off flag goes with it.
- [added] **Per-account preferences**: notifications per group and channel with one-click unsubscribe, and the time zone, language and theme follow the account.
- [changed] **Layout and speed**: three page widths, breadcrumbs, a navbar that fits a phone, cached per-user reads and links that reuse the open connection. **Hosts:** declare `text-muted` and `--container-narrow` in your stylesheet.
- [changed] **Translations say "you" informally**, and the English is American.
- [changed] **Version 1.1**: releases are `1.1.<commit count>`, from the `VERSION` file.
- [changed] **Nebulex 3.1**, the cache: no false miss when two reads promote one entry, and no `delete_all` that empties a table. **Hosts:** `mix deps.update nebulex nebulex_local nebulex_distributed nebulex_redis_adapter`.
- [changed] **Pages hold up at a million players.** `mix demo.seed --count 1000000` fills every list (now with players' sessions, KV, notifications, analytics, economy, payments, reports, friends, lobbies, bans and inventory), and `mix demo.bench` times every page's load, pagination and search against it (`stress/pages/`). What it found is fixed: All time keeps its own board (`<slug>__all_time`), a public board that lists registered players only reads a `guest` flag the database keeps on each record instead of joining every record to its user, player searches find names through trigram indexes (Postgres), the analytics pages count in the database, admin lists page on indexes, every foreign key has an index, and `KV.stream_prefix/2` walks one key family across every player in one pass (by id, a batch a query), where paging `list_entries/1` read the whole table once per page. **Hosts:** run the migrations; a large database builds the new indexes concurrently; move a job that pages `list_entries(key: …)` to walk every row onto `stream_prefix/2`.
- [added] **Smaller additions**: crawler statistics, FAQ sections on presentation pages, rate-limit-exempt IPs, KV pruning by prefix, slow query logging and `Accounts.update_user_metadata/2`.
- [removed] **IndexNow.** **Hosts:** drop `GAMEND_INDEX_NOW_*` and any `urls/1` from your sitemap source.
- [fixed] **Players dropping at once no longer run a server out of memory.** A user channel's disconnect asks `Gamend.Presence.last_socket?/1` whether it was the user's last socket, and phoenix_pubsub answered that by copying the tracker shard's whole state into the caller: ~1 MB per disconnect at 2,000 players, all queued on the one shard process. A thousand players dropping together ran a 1 GB server out of memory. It now reads the one key from the shard's table, and the other presence reads paid the same copy and now read the same way through `Gamend.Presence.keys/1`: a signaling room's peers on every relayed message, the room counts in the server stats, and a lobby's spectator count and list, once per lobby in a listing. The slow-query log (`Gamend.Repo.SlowLog`) did the same harm a second way: naming each frame's application copied every loaded application's module list into the caller, ~360 KB a line, and when the pool is what is slow every waiting query logs at once. Its lines now name the frames without the application.
- [fixed] **Sign-in and connections**: Steam sign-in works again, an unconfirmed account gets its confirmation email instead of a login link, a guest who registers gets theirs (their account stayed confirmed, so none was sent), and TLS 1.2 clients (Stripe's sandbox webhooks) connect again.
- [fixed] **Smaller fixes**: leaving a page plays no `phx-remove`, a finished chain step always has its card, generated usernames ignore the caller's `:rand` seed, `Sitemap.Cache.prune/0` reads every page, and cached logins, lock waits and races no longer leave stale state.
- [fixed] **Guest sign-in on Postgres and the analytics buffer**: a guest's activity days merge again (an `insert_all` gave them no id), an event naming a deleted account is kept without it instead of holding back every later event, and a response to a peer that closed its HTTP/2 connection is no longer logged as an error.
