# November 2026

- [changed] **A quest card that leads somewhere says so with a button.** `config :gamend_core, :quest_action` answers `{label, path}`, as `:leaderboard_action` does (`Gamend.Quests.host_action/2`), and the quests page draws the label as a button on every card it links. **Hosts:** answer `{label, path}` (the label in the reader's language); a bare path is now no link.
- [changed] **Icons are cached files, not inline SVG or data URIs.** A `hero-*` class is a mask of `/icons/<set>/<name>.svg?v=<hash>` (the 24px solid set at `/icons/<name>.svg`, the rest under `outline`, `mini`, `micro`), and `<.entity_icon>` (every avatar icon, group, quest and notification icon) draws a `<span class="icon-mask">` of the same file instead of its SVG. The browser fetches each icon once and keeps it across deploys: the stylesheet every page waits for lost its icons (65 → 51 KB compressed), and a notification row 1 KB. `GamendWeb.Icons.draw_path/1` is the versioned URL; a bare `/icons/...` URL, as an `icon_url` stores it, is now cached for a day, a versioned one for good. **Hosts:** nothing to do; a test that looked for `<svg` in an entity icon looks for `icon-mask`.
- [changed] **`/notifications` loads 50 at a time** (was 200), more on Load more.
- [fixed] **A first visit no longer jumps sideways.** The navbar's stage was guessed until the deferred `app.js` measured it, and in the auto layout the sidebar's room then slid the whole page 224 px (a layout shift of 0.8 on a desktop). `theme-init.js` now measures the header as soon as it is parsed and the stylesheets are in (a `MutationObserver` and the stylesheet's `load`, never blocking the parser); while nothing is measured, from `md` up, the shell waits unseen (`<html data-nav-fit="pending">`, shown by the fit, `app.js`, or after two seconds), and its margin transition is held.
- [added] **`flag_path/1`**: a flag's URL as `flag/1` draws it, the WebP where it is the smaller file, for markup that is not an `<img>` (an SVG `<image>`).
- [changed] **The hero's logo is no longer `fetchpriority="high"`**: it is decorative, and on a slow phone it was fetched beside the stylesheet the title waits for.
- [changed] **Pages that list players are about twice as fast.** `Gamend.Inventory.inventory/1` is cached and evicted on every committed change, as the entitlement rows are, so a host that draws a player's title from their items reads it once per player instead of once per row per render (a leaderboard's page went 15 ms → 9 ms, a page click 8 ms → 4 ms). The shell resolves its navigation once a render and hands it to its five navs (`prepared`; the quests count, the wallet and per-reader links were resolved five times). `mark_all_notifications_read/1` keeps the notifications cache when nothing was unread.
- [changed] **A dev request no longer re-checks code and migrations when nothing changed.** `GamendWeb.DevWatch` watches the reloadable apps' `lib`, `priv/gettext` and `config` and the repos' migration folders, and the endpoint's dev plugs (`GamendWeb.Plugs.DevCodeReloader`, `DevRepoStatus`) run Phoenix's reloader and `CheckRepoStatus` only after a change; the root layout's asset hashes follow each file's size and change time instead of re-reading it. A dev request on a busy laptop went from 0.2–12 s to a few ms, and ten at once from 2.3 s each to 3 ms. A compile error or pending migration still shows on every request until fixed. **Hosts:** nothing to do; `FileSystem` comes with `phoenix_live_reload`, and without it, or without a watcher the system can run (Linux with no `inotify-tools`), every request checks as before.
- [fixed] **An edited chat message is moderated as a sent one.** `Gamend.Chat.update_message/3` (the API's `PATCH /api/v1/chat/messages/:id` and the chat page's edit) skipped the mute, the word filter and the `before_chat_message` hook, so an edit could put a blocked word in a message. It now answers `:muted`, `:blocked_content` and `{:hook_rejected, reason}` as `send_message/2` does, masks and flags as a send does. The hook sees the edit with its conversation, as a send's (`chat_type`, `chat_ref_id`), and its `message_id`; only the `content` and `metadata` it answers are saved. Slow mode stays a send's. **Hosts:** a `chat_update:` controller written to moderate edits can go.
- [changed] **A host's stylesheet is only its own look: core's is one import.** `assets/css/gamend.css` (now in the package) brings Tailwind, core's sources, the loading variants, heroicons, core's classes (`btn-surface`, `card-hover`, `text-muted`, `max-w-narrow`, `nudge`, in the `assets/vendor/gamend.js` plugin) and the base styles of core's pages (Inter, the background icons' drift, Markdown, changelog pills, touch targets, iOS zoom, docs code). The `gamend_assets` compiler (and `mix gamend.assets`, `--check`) writes `assets/vendor/gamend/`, pointers to core wherever it is, on every compile. Markdown text takes a colour, not an opacity, and the touch targets leave a game's keys their own width. The unused flag-icons plugin is gone. **Hosts:** add `compilers: Mix.compilers() ++ [:gamend_assets]`, put `/assets/vendor/gamend/` in `.gitignore`, start `app.css` with `@import "../vendor/gamend/gamend.css";`, load daisyUI through `../vendor/gamend/daisyui` and `../vendor/gamend/daisyui-theme`, and delete what core now brings (the dual-path `@source` lines, heroicons, the variants, the copied blocks) and the old `assets/vendor` wrappers.
- [added] **`nudge`: the one next step on a page moves.** The class goes on the button or card a reader should press next; a chevron (the hero's scroll cue) bounces before it (`nudge-top`: above it) and on every second landing a ring grows out of its edge. The theme JSON picks the move, `"nudge": {"move": "pointer ring", "rhythm": "always"}` (`pointer`, `ring`, `hop`, `shine`, or `pointer` with one; `always` or `rest`), written on `<html data-nudge data-nudge-rhythm>`; reduced motion gets a steady ring. A hero button takes `"nudge": true`, and the quests page nudges the first Claim.
- [added] **`form_heading/1`: a long form's action stays in sight.** Back, the title and the form's submit (`form="…"`, outside the form) in a heading that sticks under the navbar; a `note` slot says why the action is off.
- [added] **A label row on a leaderboard can draw its own avatar.** `row_avatar/2` on `config :gamend_web, :leaderboard_views` answers any markup for a row with no account (a picture, an icon, a flag), and `player_card/1`'s `avatar` draws it in the avatar's box.

On the `latest` release as `gamend-unreal-plugin.zip`. The C++ SDK marks its classes `GAMEND_EXPORT` for a shared build, and compiles clean as C++20.

Installs from a git URL, `https://github.com/appsinacup/gamend-unity.git`, and is on the `latest` release as `gamend-unity-sdk.tgz`.
- [added] **Rust SDK**: every player operation, typed models, realtime with protobuf, and the conformance scenario, for Bevy, Fyrox, macroquad and tools. On crates.io as `gamend` and on the `latest` release as `gamend-rust-sdk.tar.gz`.

A button that leaves with no link says `data-leaves-form`. On the account tab and a group's edit form.

Provider variables are on Payments, and the database, cache, cluster, TLS and test email are under Services on System.

The blog, changelog, roadmap, chat, notifications, account and sign-in titles now pass their link's `"tone"`, and `header/1` takes `tone`.

- [fixed] **An empty `GAMEND_HTTP_ALLOWED_ORIGINS` lets the game socket take any origin**, as its docs said: Phoenix's default had refused every origin but `GAMEND_HTTP_HOST`, so a web build served elsewhere (itch.io, a CDN) got 403 on `/socket` while the API answered it. The pages' socket (`/live`, the session cookie) keeps to the server's own names and the list. With a list set, both sockets take it and the server's own names.
- [fixed] **A `regex:` entry in `GAMEND_HTTP_ALLOWED_ORIGINS` no longer breaks WebSockets.** Phoenix's `check_origin` takes origins as strings, so the compiled pattern raised on the first socket; a list holding one is checked by `GamendWeb.Http.origin_allowed?/2`.

- [added] **Containers.** `Gamend.Containers` drives long-lived OCI containers and their images through the `podman` CLI (create, start, stop, pause, kill, update limits, logs, exec, volumes, pull, tag and untag, the machine's `info/0` and every container's `stats/0`, a one-shot `output/3` that takes limits and a runtime for a build of someone else's code), with a hardening floor on every container and secrets through a 0600 env file (`write_env_file/2`). `update/2` takes CPUs, memory and pids together: podman 5 drops the limits an update leaves out. What it found is fixed: All time keeps its own board (`<slug>__all_time`), a public board that lists registered players only reads a `guest` flag the database keeps on each record instead of joining every record to its user, player searches find names through trigram indexes (Postgres), the analytics pages count in the database, admin lists page on indexes, every foreign key has an index, and `KV.stream_prefix/2` walks one key family across every player in one pass (by id, a batch a query), where paging `list_entries/1` read the whole table once per page. **Hosts:** run the migrations; a large database builds the new indexes concurrently; move a job that pages `list_entries(key: …)` to walk every row onto `stream_prefix/2`.

- [fixed] **Players dropping at once no longer run a server out of memory.** A user channel's disconnect asks `Gamend.Presence.last_socket?/1` whether it was the user's last socket, and phoenix_pubsub answered that by copying the tracker shard's whole state into the caller: ~1 MB per disconnect at 2,000 players, all queued on the one shard process. A thousand players dropping together ran a 1 GB server out of memory. It now reads the one key from the shard's table, and the other presence reads paid the same copy and now read the same way through `Gamend.Presence.keys/1`: a signaling room's peers on every relayed message, the room counts in the server stats, and a lobby's spectator count and list, once per lobby in a listing. The slow-query log (`Gamend.Repo.SlowLog`) did the same harm a second way: naming each frame's application copied every loaded application's module list into the caller, ~360 KB a line, and when the pool is what is slow every waiting query logs at once.
